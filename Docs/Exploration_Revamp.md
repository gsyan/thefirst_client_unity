## 1. 확정 사항

### 1-1. 성능포인트 시스템

**함체 및 모듈의 그레이드 개념 완전 폐지.** 성능은 그레이드가 아니라 프리셋에 배분된 성능포인트 총량으로 결정됨.

- **[수정] 성능포인트 총량은 프리셋마다 가변** (500/750/1000+...) — "모든 함선 동일 1000"이라는 이전 전제는 폐기. "1000"은 고정 총량이 아니라 최상급 프리셋의 상한 기준점 역할
  - 초반 함선이 여전히 쓸모 있으려면 총량이 같을 필요는 없고, 대신 **지휘력 코스트가 포인트량보다 더 가파르게 증가**하도록 설계 — 예: 500p 함선(빔1개, 코스트100) vs 1000p 함선(빔3개, 코스트500). 포인트 2배에 코스트 5배, 무기 개수는 3배 → 지휘력을 많이 쓸수록 코스트당 성능이 체감(한계효용 감소). 저포인트 프리셋은 "약하지만 가성비 좋음"이라는 존재 이유를 가짐 (§1-2 코스트-성능 곡선 원칙과 연결)
- **프리셋 선택방식**: 유저가 직접 포인트를 배분하지 않음. 게임 제작자가 CSV/데이터로 만든 함선 프리셋(배분 완료 상태)을 지휘관 레벨 등 조건에 따라 언락/선택. 함선 A/B/C의 포인트 배분은 기본적으로 유저에게 잠긴 고정값 — 자유 재조정 가능하면 함선 간 정체성이 무의미해지기 때문
  - 기존 모듈포인트/미네랄 투자 성장 시스템(`DataTableModule.modulePointCost`, `mineralCost`, `Commander.modulePoint`/`mineral` 소모, `UITabShip` 레벨업 흐름)은 완전 폐기
  - 프리셋 포인트 배분 내에서 유저 커스터마이징 기능은 별도 옵션 레이어(예: VIP 전용)로 분리, 기본 시스템과 독립
- **배분 대상 스탯**: 체력, 실드, 요격체, 빔, 미사일, 함재기, 선회력(신규 — 기존 `CapabilityProfile`엔 없었음), 수리능력
- **카테고리별 "장착"(고정 코스트) + "강화"(1p=+0.1 선형) 2단 구조**:
  - 장착: 모듈 1개를 슬롯에 적용하는 고정 코스트 (예: 빔 모듈 1개 = 200p, 기본 공격력20). 추가 장착은 다시 같은 코스트 지불
  - 강화: 이미 장착된 모듈 하나에 1p씩 투입해 능력치 +0.1 가산 (정확한 계수는 실측으로 확정 예정)
  - 함재기/격납고: 격납고 1개 장착 = 함재기 3대 세트(200p). 강화는 기존 격납고의 함재기 스탯 강화
    - **함재기 확산(장착) vs 강화 검증 완료**: 동일 투자량(400p) 비교 시 확산(10기×공격10)이 강화(5기×공격30)를 집중/랜덤 타겟팅 모두에서 100% 승리 (실제 데이터: 체력50/공격10/쿨다운10초 기준). 오버킬 낭비 + 란체스터 법칙 중첩 효과 — 별도 인위적 수확체감 계수 불필요, 이 메커니즘에 밸런싱 위임. 다만 강화가 지나치게 무의미해질 위험 있어 계수/코스트 후속 조정 여지 있음
    - **강화 서브스탯 4종 분리**: 기존 코드에 이미 존재하는 두 전투 페이즈(`AircraftBase.cs`의 `Dogfight` 상태, `Phase_AttackShip`)에 대응하되, 이름 붙은 묶음(파이터/공격기)이 아니라 완전히 독립된 4개 서브스탯으로 분리 — **함선 대상 공격력**(`Phase_AttackShip`용), **함재기 대상 공격력**(도그파이트용), **ammo**, **체력**. 강화 1p=1서브스탯 선택, 실드와 동일한 1p=1선택 원칙 적용. 구체 계수는 디자이너 튜닝 영역 — 실드 회복속도 사례처럼 특정 서브스탯이 압도적 최적해로 수렴할 수 있어 실측 후 조정
- **함선 타입(공격/수비/수리)**: 하드코딩 카테고리가 아니라 포인트 배분 비율에서 드러나는 경향치
  - 타입별 외형 색상 표현: 머티리얼 틴트는 불가(색이 텍스처에 베이크되어 있음) → 에셋팩에 이미 있는 Beige/Blue/Grey/Red/White 5종 프리메이드 머티리얼로 교체하는 방식 채택. 신규 아트 제작은 불필요하나 실사용 시 참조가 생겨 빌드 용량 증가함. 최대 동시 렌더링 함선 30척 기준 배칭 손실은 무시 가능한 수준
- **보상카드 효과**: 최종 반영된 능력치에 곱연산 버프(예: ×1.01, ×1.02...) 적용
- **연산 순서**: 전위/후위 보정과 보상카드 버프는 모두 곱연산이라 순서 무관. 가산이 섞이면 가산을 먼저 적용 후 곱연산 일괄 적용
- **함선 위치별 능력치 보정**: 전위 배치 시 공격력↑/방어력↓, 후위 배치 시 공격력↓/방어력↑ (구체 계수는 미정, 실측 필요)
- **함선 레벨**: 보상카드로 부여, 해당 탐험 동안만 유지되는 임시 버프 (영구 저장 아님, 세션 스코프)
- **미사일-빔 상호작용**: 미사일과 충돌한 빔의 공격력이 미사일 등급에 따라 차감됨 (현재는 등급 무관 완전 차폐 → 등급별 부분 차폐로 변경, 구체 차감 수치는 미정)

**함체(외형) 결정 방식**
- **함선 프리셋 데이터에 프리팹 이름을 직접 지정**(고정값으로 박아둠). 프리셋의 스탯 정체성(빔 특화, 함재기 특화 등)이 정해지면, 그에 어울리는 함체를 디자이너가 제작하거나 기존 에셋(t1~t14 등)을 골라 배정
- 슬롯 배치는 프리팹마다 필요한 만큼 미리 구성(그레이드별 슬롯 수 자동 계산 로직은 불필요해짐)

### 1-2. 지휘관 레벨 / 지휘력 / 탐험 포인트

| 자원 | 획득 방법 | 역할 | 리셋 여부 |
|---|---|---|---|
| 지휘관 레벨 | 경험치 누적 | ① 배치 가능 함선 개수 상한 (기존 `DataTableCommanderLevel` shipCount 로직 재사용) ② 가용 함선 리스트에 신규 함선 추가(락 상태) | 영구 |
| 지휘력 | 탐험 포인트로 "최대치" 구매 | 함대 배치용 **점유형**(소모 아님, 반환 가능) 예산. 프리셋별 코스트 다름 | 매 탐험 시도마다 최대치로 초기화 |
| 탐험 포인트 | 셀 클리어 시 **상대 적함대의 총 성능포인트만큼** 적립. **탈출 성공 시 100% 지급, 실패 시 50% 지급** | ① 지휘력 최대치 증가 ② 락된 함선 영구 언락 (언락은 이 방식 하나뿐) | 소비형 |

- 지휘력 최대치는 함대 빈자리 개수 정도면 충분한 수준으로 설계 → 탐험 포인트가 자연스럽게 "함선 리스트 영구 언락" 쪽에 더 쓰이도록 유도
- 개별 함선의 지휘력 코스트는 투자 비율이 아니라 프리셋에 고정된 값(강한 프리셋일수록 코스트도 높음)
- 지휘력은 점유(반환 가능) 구조 — 함선을 빼면 즉시 회수, 셀마다 함대 재세팅 가능해야 하므로 필수
- **프리셋 코스트-성능 곡선 설계 원칙**: 지휘력 총량이 예산(포인트) 구조이기 때문에, 비싼 프리셋을 채우고 남는 자투리를 저비용 프리셋으로 메우는 구도가 자연스럽게 발생함. 이걸 신뢰할 만하게 만들려면 **코스트가 오를수록 코스트당 성능(총 성능포인트/지휘력코스트)이 체감(diminishing)하도록 설계** — 예: 코스트 20배(100→2000)에 성능은 10배만 상승. 이러면 저비용 프리셋은 "가성비"로 항상 편성할 이유가 생기고, 숫자가 우연히 안 맞아떨어지는 것에 기댈 필요가 없음
  - **주의**: 체감이 지나치면 "고비용 프리셋을 쓸 이유가 없다"는 반대 문제가 생김 — 저비용도 쓸모 있으면서 고비용이 명백히 더 강하다는 균형점을 잡아야 함. 구체 곡선 수치는 실측 튜닝 필요 (미정)

### 1-3. 그리드 셀 이동 UX

- **그리드 규격**: 존이 진행될수록 점진 확장 (3x3 → 5x5 → 7x7 → 7x10...), 정사각형 아닌 직사각형도 가능. 세로 영역이 한계에 다다르면 가로로만 길어지고 좌우 스크롤로 탐색 — 고정 5x5 레이아웃이 아니라 가로 스크롤뷰(ScrollRect) 기반 동적 레이아웃 필요. 시작점/탈출점 존재(존 시드 기반 고정 배치, 구체 규칙은 `Exploration_Grid_Implementation.md` 참고)
- **이동 방식**: 인접 셀만 선택 이동(노드형, 4방향), 이동 가능한 셀은 UI상에서 색 깜빡임으로 강조 표시 — 현재 `UIZoneConnector`/`UIZoneTabNode` 구조 재활용
- **전투 트리거**: 정찰 후 수동 확인(자동 즉시 전투 아님)
- **빈 셀**: 낮은 확률로 적 함대 없이 탐험 포인트만 획득하는 셀 존재 (공식은 "적 함대 총 성능포인트 기준"과 별개로 정해야 함, 미정)
- **재방문**: 클리어한 셀도 자유 재방문 가능. 적 재등장 + 탐험 포인트 재획득 가능(파밍형), 탈출 성공 시에만 100% 지급
- **워프인 연출**: 최초/재방문 구분 없이 매번 재생 (설정상 셀 간 거리는 워프가 필요할 만큼 멂)
- **셀 클리어 보상**: 보상카드 3개 중 1개 선택 (예: 함선 레벨 +1, 미언락 함선 이용권 등) — 보상카드 리스트/데이터 테이블 별도 구성 필요

**셀 진입 연출 및 정찰/세팅 UI 흐름**
1. 내 함대 워프인 → 적 함대 워프인. 양쪽 완료 후에만 화면 분할 + 터치 활성화
2. 기본 상태: 좌측=적함대 3D 뷰, 우측=내함대 3D 뷰(카메라 2대, 좌우 분할). 가운데 "전투시작"/"함대편집" 버튼
3. **정보 패널은 항상 우측 고정, 3D 뷰는 항상 좌측 고정 — 선택된 함선의 소속 함대가 좌측을 차지**
   - 적 함선 터치: 좌측 유지(적함대), 우측이 정보 패널로 전환
   - 내 함선 터치: 내함대 뷰가 좌측으로 이동, 우측이 정보 패널로 전환(함대편집 기능 포함, 3열: ①가용 함선 리스트 ②배치된 함선 리스트 ③선택 함선 정보)
4. 허공 터치 시 정보 패널 닫히고 기본 상태로 복귀

**함대 슬롯 관리 방식**: 3x3 등 공간형(그리드) 배치 UI는 기각 — UI가 지나치게 커짐. **리스트 기반 슬롯 관리**로 확정. 배치된 함선 리스트의 각 항목에 전방/후방 토글이 별도로 붙는 구조 (공간 배치가 아니라 리스트 순서 + 개별 속성)

**구현 방식**: RenderTexture + RawImage (각 함대 카메라 → RenderTexture → Canvas RawImage). RectTransform 트윈으로 이동/축소, UI 레이아웃과 자연스럽게 통합. `Camera.rect` 직접 애니메이션 방식은 레이아웃 통합이 불편해 기각. RenderTexture 해상도/갱신주기는 모바일 기준 구현 시 확인 필요.

### 1-4. 실드 / 요격체 / 함체 체력 역할 분리

- **함체 체력(HP)**: 패시브 자동회복 없음 → **셀 이동 시에도 이월**, 여러 셀에 걸쳐 누적 소모되는 런(Run) 전체의 최종 버퍼
  - **회복 수단**: "공작선" — 수리능력에 특화된 별도 함선 타입이 함대를 편성해 **패시브로 함대 체력을 지속 회복**. 공작선 자체가 함대 슬롯(지휘력)을 하나 차지하므로, 슬롯 여유가 있는 중후반 유저(지휘관 레벨로 함선 개수 확장된 상태)의 전략적 선택지 — 초반엔 슬롯 부족으로 사실상 회복 수단 없음
  - 추가로 **탐험 포인트를 소모해 일시적으로 수리력을 배수(곱연산)로 증폭**하는 능동 기능도 존재. 여기서 쓰는 탐험 포인트는 **은행에 이미 쌓인 영구 자산**(과거 탐험들에서 확정 지급받은 포인트) — 이번 런에서 지금 적립 중인 포인트는 탈출 성공/실패로 확정되기 전이라 아직 "내 것"이 아니므로 소모 대상이 아님. 즉 지휘력 최대치 증가·함선 언락에 쓸 미래 성장 자산을 지금 태워서 생존을 사는 무거운 트레이드오프 — 실패 시 50%만 받으므로 위험할 때 선제 투자할지, 아껴서 성장에 쓸지의 판단이 핵심. §1-6의 "실패 후 광고 시청 재도전"과는 별개의 사전 예방형 안전장치
- **실드/요격체**: 회복하는 자원이므로 **셀 진입 시마다 풀로 초기화**. 공격 모듈(빔/미사일/함재기) 쿨다운도 셀마다 초기화
- 역할 분리: HP=여러 셀에 걸친 누적 누출을 버티는 자원, 실드/요격체=매 전투(셀) 단위로 반복되는 단일 전투 최적화 문제
- **요격체 기본 동작**: N개가 함대 전방(빔 발사 경로를 피해)에 떠 있다가, 근처로 접근하는 적 미사일에 순서대로 반응해 요격(폭파 소모). 소모 후 딜레이 지나면 1개씩 보충
- **요격체 재고 증가**: 장착식 계단 — 1개당 100포인트 고정
- **실드 1차 초안 수치**: 장착 200p → 기본 게이지100·딜레이5초·회복속도5게이지/초(풀회복 20초). 강화는 1p=1서브스탯(게이지/딜레이/회복속도 중 택1) 선택: 게이지 +0.5/p, 딜레이 −0.02초/p(최소1초), 회복속도 +0.1게이지초/p
- **실드 재가동 규칙**: 딜레이(완전 무방비) 종료 후 즉시 "가동" 상태 진입 — 이 상태에서 회복과 피격 방어가 동시에 일어남(게이지 있는 만큼 즉시 방어, 소진되면 딜레이로 복귀). "풀게이지까지 완전 무방비" 방식은 기각(회복속도가 거의 모든 상황에서 압도적 최적해로 수렴하는 문제 확인)

### 1-5. 타겟팅 방식 변경

적 함선의 전위/후위 배치 기준으로 전위 우선 타겟. 같은 레이어(같은 전위 또는 같은 후위) 내에서는 현행 유지(함선 회전 최소화) — `SpaceShip.ApplyTargetingRules()`의 `ETargetingRule` 비트마스크 필터에 규칙 추가로 구현 가능

### 1-6. 광고 SDK

프로젝트는 **Google Mobile Ads(AdMob v11.0.0) 단독 사용**, 다른 mediation SDK 없음. 핵심 클래스 `Assets/Scripts/System/Ad/AdManager.cs`(`LoadRewardedAd()`, `ShowRewardedAd(callback)`). **광고 길이/종류 선택 기능은 지원되지 않음** — AdMob 리워드 광고 API 자체가 네트워크 자동 배정 구조. 탐험 실패 후 재도전용 광고는 기존 `UITabExploration.OnWatchAdForDoubleReward()`와 같은 `ShowRewardedAd` 흐름을 재사용. 재도전 횟수 제한 없음.

### 1-7. 서버/클라 역할 분담

클라는 존 입장·셀 클리어·탈출 시점에 서버로 메시지 전송, 서버가 authoritative하게 기록. 탈출 시 보상 지급 여부를 서버가 기록하고 미수령 보상은 다음 접속 시 지급 — 이 로직은 이미 존재(`PendingStageRewardRequest/Response.java`, `ClaimZoneRewardRequest/Response.java`). 신규 탐험 포인트/보상카드도 동일 패턴 재사용.

## 3. 신규 설계 필요 항목

1. 5x5 그리드 + 셀 이동/시작점·탈출점 시스템
2. 셀 클리어 보상카드 3택1 + 보상카드 데이터 테이블
3. 탐험 포인트 적립/지급(성공 100%/실패 50%) + 실패 후 광고 이어하기
4. 함선 "성능포인트 분배(총량 가변)" 시스템 (현재 `CapabilityProfile` 고정 스탯 → 가변 배분 구조로 전환)
5. 함선 위치(전방/후방) 기반 능력치 보정 로직
6. 실드 게이지 + 회복 로직
7. 요격체(미사일 요격) 컴포넌트
8. 미사일-빔 충돌 시 미사일 등급별 공격력 차감 로직 (현재 완전 차폐 → 부분 차폐)
9. 지휘력(함대 배치 코스트) 시스템
10. 함선 레벨(보상카드 기반, 탐험 한정 유지) - 세션 스코프 데이터
11. 셀 진입 연출: 듀얼 카메라 좌우 분할 뷰포트 + 터치 시 뷰포트 전환(정찰⇄편집 UI) 시스템
